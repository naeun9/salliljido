# 02. 미구현/연결 대기 항목

화면을 하나씩 구현하면서 "지금은 스킵하고 나중에 연결" 하기로 한 것들을
모아둔다. 새 화면을 구현할 때마다 여기 추가하고, 연결이 끝나면 완료로 표시한다.

---

## 0. 우선순위 (2026-08-24 전체 점검 기준 · 마감 9/21)

남은 기간 약 4주. 아래 순서대로 처리하면 마감까지 안전하다.

### A. 필수 — 이게 없으면 심사에서 기능이 끊겨 보인다

1. **담은 체험이 체류 계획·예상 비용 탭으로 안 넘어간다.**
   둘러보기는 실제 `contentId`를, 나머지 두 탭은 목업 id(`e1`~`e8`)를 쓴다.
   체험을 담아도 일정표에 안 뜨고 체험비가 0원. 서비스의 핵심 흐름
   (둘러보기 → 계획 → 비용)이 실제로 끊겨 있다.
   → `ScheduleTab`/`CostTab` 실데이터 연동. docs/03-api-check.md §15.
2. **체험 소요시간·가격이 API에 없다 (1번과 함께 결정해야 함).**
   예상 비용의 "체험비" 항목을 어떻게 채울지 제품 판단 필요
   (사용자 입력으로 받기 / 항목 자체를 빼기 / 무료·유료만 표기 등).
3. **새로고침하면 체류 조건이 사라진다.** `SearchContext`가 메모리라
   `/plan/:id`에서 새로고침하거나 URL을 직접 열면 기간·라이프스타일이
   초기화된다. 게다가 배너는 "2주"라고 쓰는데 계산은 7일로 도는
   불일치까지 생긴다(§ 아래 "화면 간 연결" 항목).
   → 조건을 URL 쿼리에 싣거나 `SearchContext`도 localStorage로.
4. **없는 URL이 완전한 빈 화면.** `App.jsx`에 `path="*"` 캐치올이 없다.
   심사위원이 주소를 잘못 입력하면 헤더조차 없는 백지가 나온다.
   → `RegionNotFound`처럼 이미 있는 컴포넌트를 재사용하면 금방 끝난다.
5. ~~**지도가 아직 목업이다**~~ — **완료(2026-08-26).** 지도 4곳 전부
   실제 카카오맵으로 교체했다(추천 결과 미니맵 / 둘러보기 사이드 /
   체류 계획 사이드 / 최종 계획 체류 범위). SDK를 못 불러오면 목업
   셸로 폴백한다. 아래 "카카오맵" 절 참고.
6. ~~**지원 프로그램 실제 공고 수집(팀 작업).**~~ — **1차 완료
   (2026-09-12).** 공식 공고를 확인한 10건을 넣었다(체류 여행 지원 8 +
   귀농귀촌 살아보기 2). 새 공고가 열릴 때마다
   `data/supportPrograms/` 아래 광역 파일에 한 건씩 더하면 된다 —
   양식은 `data/supportPrograms.js` 상단 주석 참고. 아직 못 넣은
   지역과 그 이유도 같은 주석에 적어 뒀다.

### B. 있으면 좋은 것 — 완성도

7. 토스트(ToastStack) — design 전반에 깔려 있는데 통째로 빠져 있다.
8. 구글 OAuth 실연동 (`VITE_GOOGLE_CLIENT_ID` 비어 있음).
9. 계획 이름 중복 처리(`uniquePlanName`).
10. 숙소 예약 링크를 `contentId` 기반 개별 상세 페이지로.
11. RegionResult/RegionIntro의 추천 점수를 실제 API로.

### C. 안 해도 되는 것 — 판단해서 접어도 됨

12. ~~`overview`(최종 계획) 화면~~ — **구현 완료**(2026-08-26).
    `/plan/:regionId/overview`. design 1446-1696줄을 그대로 옮겼고,
    인쇄·엑셀 내보내기만 UI로 남기고 동작은 아래 15번으로 미뤘다.
13. 마감 임박 알림 설정 — design에서도 죽어 있던 기능.
15. **내보내기(인쇄/PDF·엑셀) 실동작** — 최종 계획 화면의 드롭다운은
    원본대로 있지만 지금은 "내보내기는 아직 준비 중이에요."만 뜬다.
    붙일 것: (a) 인쇄용 CSS — 원본은 `data-print-hide` 속성으로 헤더·
    버튼을 숨기고 `window.print()`를 부른다(design 3384줄). 속성은 이미
    같은 자리에 다 달아뒀으니 `@media print` 규칙만 쓰면 된다.
    (b) 엑셀 — design 2046줄 `exportXlsx(name, days)`가 일정표와
    `cbBars`를 시트 2장으로 만든다. `buildFullSchedule()`과
    `buildCostBars()`가 이미 같은 모양의 데이터를 주므로 직렬화만 하면
    된다. 외부 라이브러리(xlsx) 추가 여부는 판단 필요.
14. 스캐폴딩 스텁 파일 13개 정리(아래 "코드 정리" 항목).

## 애니메이션 전멸 버그 + 캐러셀 시작 위치 (2026-08-29)

- **CSS Modules가 animation 이름을 해시해서 애니메이션 8개가 전부 죽어 있었다.**
  `@keyframes`는 `styles/global.css`(전역)에 있는데 모듈(.module.css)에서
  `animation: slj-bob …`으로 부르면 이름이 `_slj-bob_해시_1`로 바뀌어
  정의를 못 찾는다. 실측으로 확인했다 — SCROLL 표시 이동량 0px.
  죽어 있던 것: 히어로 SCROLL bob, Skeleton shimmer, 다시 만들기 스피너,
  AuthGate·ExploreTab 페이드, ConfirmModal 페이드·라이즈, NameDialog 라이즈.
  - 고친 방법: 전역 유틸리티 클래스(`.slj-anim-*`)를 global.css에 두고 JSX에서
    모듈 클래스와 함께 붙인다. `animation: :global(name)` 문법은 Vite postcss가
    파싱하지 못한다("Double colon" 에러). 값은 옮기기 전 그대로다.
  - [ ] 앞으로 모듈 CSS에 `animation:`을 새로 쓰면 같은 함정에 빠진다.
        전역 클래스를 쓰거나 keyframes를 그 모듈 안에 정의할 것.
- **캐러셀 시작 위치** — design은 페이지 로드와 함께 타이머를 돌려서(2185-2190줄)
  홈 위쪽을 읽다 내려오면 이미 2~3번째 지역이 떠 있었다. IntersectionObserver로
  섹션이 절반 보일 때 1번부터 시작하고 화면 밖에서는 멈추게 했다. 사용자가 직접
  넘긴 뒤에는 자동재생을 되살리지 않는다(design halt 규칙 유지).
- **검증 방법을 바꿨다**: 정지 스크린샷 대신 실제 값 변화로 확인한다.
  bob은 요소 top이 827→833(6px), shimmer는 background-position 변화,
  스피너는 transform 8프레임 모두 다른 값, 캐러셀은 transform 기준
  슬라이드 인덱스 추적.

## 게이트웨이 장애 대비 (2026-09-06)

계기: 이날 `apis.data.go.kr`(공공데이터포털 API 게이트웨이)가 몇 시간 동안
응답하지 않았다. 우리 키·코드 문제가 아니라는 근거는 아래와 같다.

- 같은 호스트의 **다른 기관 API(기상청 1360000)도 똑같이 타임아웃**.
- `www.data.go.kr`(179ms)·`tong.visitkorea.or.kr`(224ms)은 정상 → 망 문제 아님.
- TCP 연결(27.101.236.63:80/443)은 맺어지는데 HTTP 응답이 오지 않는다.
- **Vercel 서울 리전 함수에서도 동일** → 특정 PC·회선 문제 아님.
- `api/`·`vite.config.js`는 6커밋째 변경 없고, 같은 코드로 몇 시간 전까지
  정상 조회됐다.

### 1. 타임아웃 4.2초 × 2회 (기존: 8초 1회)

관찰한 실패 방식이 **"연결은 받아 놓고 답을 주지 않는" 형태**였다.
9초를 줘도 12번 전부 실패했고 30초를 줘도 마찬가지였다. 반면 새로 연
연결은 가끔 뚫렸다(12번 중 1번, 7.5초). 즉 죽은 소켓을 오래 붙들고 있어
봐야 얻는 게 없고, **새 연결을 한 번 더 여는 쪽에 값이 있다.**

정상일 때 이 호출의 실측 응답은 114~317ms다(§13, 500건 조회 기준).
4.2초는 그 13배가 넘어 정상 응답을 자를 위험이 없다.

- 총예산 4.2 × 2 = **8.4초**. Vercel Hobby 함수 실행 한도 10초 안이다.
- 실측: `/api/tour/area-based` 8.451초, `/api/tour/detail` 8.441초
  (detail은 두 호출을 병렬로 보내므로 재시도가 붙어도 벽시계는 그대로).
  여유 약 1.55초. **두 값을 바꿀 때는 곱한 값을 반드시 다시 계산할 것.**
- 재시도는 1회, 백오프 없이 즉시. 응답을 받아 온 실패(에러코드)는 다시
  불러도 같은 답이라 재시도하지 않는다(`isUnreachable`).

### 2. 타임아웃일 때만 다른 안내

`errorCode: "TIMEOUT"`을 502 본문에 실어 보낸다(포털 에러코드는 전부
숫자라 겹치지 않는다). 문구를 문자열로 비교하지 않으려고 코드로 준다.

- 둘러보기 목록: 제목이 "정보를 불러오지 못했어요" → **"관광공사 서버가
  응답하지 않습니다"**. 설명("잠시 후 다시 시도해 주세요")과 "다시 시도"
  버튼은 그대로. 제목에 제공처를 적어야 우리 서비스 고장으로 읽히지 않는다.
- 상세 모달: "상세 정보를 불러오지 못해…" → "**관광공사 서버가 응답하지
  않아** 기본 정보만 보여 드려요."
- 그 밖의 실패는 기존 문구 그대로.

### 3. 목록이 죽어도 나머지는 산다 (장애 중 실측)

13개 라우트 전수 확인 — 콘솔 에러 0, 가로 넘침 0.

| 화면 | 장애 중 상태 |

  오버레이다(SidebarMap.jsx 주석). 실제로 보이는 것은 1개.

  한꺼번에 받아 나누는 구조다(§12).

## 홈 히어로 배경 개선 (2026-09-08)

### 2-1. 전환 중 뒷배경이 비치던 문제

원인은 크로스페이드 방식이었다. 두 장의 opacity를 서로 반대로 움직이면
한가운데서 둘 다 0.5가 되고, 겹친 불투명도는 1-(0.5×0.5)=0.75라 **뒤의 빗금
배경이 25% 비쳤다.**

바닥 한 장을 불투명하게 둔 채 그 위에 다음 장을 덮어씌우는 방식으로 바꿨다.
바닥은 늘 opacity 1이라 어느 순간에도 100% 가려진다.

- 페이드가 끝나면(1.1초) 바닥을 새 사진으로 갈아 끼운다. 두 층을 **배열로**
  그리고 key를 사진 주소로 둬서, 나타나던 층이 바닥이 될 때 React가 같은
  DOM을 재사용한다 — 확대가 처음부터 다시 시작되지 않는다.
- 페이드는 바깥 층, 확대는 안쪽 층에 나눠 걸었다. 한 요소에 둘을 같이 걸면
  페이드 클래스를 뗄 때 확대까지 재시작된다.
- **검증**: 빗금 배경을 마젠타(#FF00FF)로 바꾸고 전환 구간을 0.2초 간격으로
  훑었다. 페이드 0.519·0.899·0.999 프레임을 포함해 **마젠타 화소 0개**
  (1,152,000화소 전수 검사). 바닥 층 opacity는 내내 1.000.

- 구글 로그인은 아직 키가 없어 동작하지 않지만(§4 구글 OAuth 항목), 게시를
  위해 필요한 문서라 로그인 시 받는 항목을 명시했다.

검증: 두 화면 × 390/900/1280px에서 헤더·푸터 정상, 가로 넘침 0, 콘솔 에러 0.
푸터·로그인 화면의 링크가 실제로 이동하는 것까지 클릭으로 확인했다.
15개 라우트 회귀 확인도 통과.

## 구글 로그인 연동 (2026-09-08)

`VITE_GOOGLE_CLIENT_ID`가 채워져서 Login.jsx의 TODO를 실제 연동으로 바꿨다.

### 흐름 선택 — 토큰 흐름(우리 버튼)

구글이 주는 기본 버튼(`google.accounts.id.renderButton`)을 쓰면 design의
"구글 계정으로 계속하기" 자리를 구글 버튼으로 갈아 끼워야 해서 화면이 바뀐다.
그래서 `google.accounts.oauth2.initTokenClient`(토큰 흐름)를 골랐다 — 우리
버튼의 클릭에서 팝업을 띄우므로 design을 그대로 두고, 사용자 동작에서
시작하니 팝업 차단도 잘 걸리지 않는다.

- **패키지 설치 없음.** 구글 스크립트(`accounts.google.com/gsi/client`) 하나만
  붙인다. 로더 구조는 카카오맵(services/kakaoMap.js)과 같다.
  번들 증가는 gzip 기준 약 0.3KB(우리 코드만).
- 대가: 프로필을 읽으려고 `oauth2/v3/userinfo`를 한 번 더 부른다. 요청 권한은
  `email profile`뿐이다.

### 저장 범위

`salliljido.auth.v1`에 `{ auth, hasLoggedInBefore, profile }`만 넣는다.
profile은 `{ name, email, picture }` 세 값뿐이고, **액세스 토큰은 지역 변수로만
쓰고 곧바로 버린다.** 로그아웃하면 profile도 같이 지운다.

- 실측: 로그인 뒤 localStorage 전체에 가짜 토큰 문자열이 없고, "token"이라는
  글자 자체가 없다.
- 번들 검사: `client_secret` 0건(암시적 흐름이라 필요 없다), `access_token`은
  우리 코드의 속성명 2건뿐.
- 개인정보처리방침 §1에 "토큰은 한 번 읽는 데만 쓰고 저장하지 않는다"를 더해
  코드와 문서를 맞췄다.

### 화면

- 헤더 아바타에 프로필 사진, 없으면 이름 첫 글자(데모는 예전처럼 "데").
  드롭다운 맨 위에 이름·이메일 한 줄. 데모 배지는 데모일 때만(원래 그랬다).
- `.avatarBtn`에 `position: relative; overflow: hidden`만 더했다 — 사진을 원
  안에 겹치기 위한 것으로 크기·색·테두리는 design 그대로다.

### [ ] 남은 것 — 구글 콘솔에 자바스크립트 원본 등록

실제 팝업까지 띄워 보니 구글이 막는다:

> Access blocked: Authorization Error — 앱 개발자라면 Google Cloud Console에서
> 자바스크립트 출처를 등록하세요.

client_id는 제대로 실려 나가고 GIS 스크립트도 200으로 내려온다. **승인된
자바스크립트 원본**에 아래 두 개를 등록해야 로그인이 완료된다.

- `http://localhost:5173`
- `https://salliljido-taupe.vercel.app`

포트가 5173에 고정되도록 `vite.config.js`에 `server: { port: 5173, strictPort: true }`를
넣었다 — 기본값이면 포트가 5174·5175로 옮겨 다녀 등록한 주소와 어긋난다.
