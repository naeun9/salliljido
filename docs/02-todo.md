# 02. 미구현/연결 대기 항목

화면을 하나씩 구현하면서 "지금은 스킵하고 나중에 연결" 하기로 한 것들을
모아둔다. 새 화면을 구현할 때마다 여기 추가하고, 연결이 끝나면 완료로 표시한다.

---

## 0. 우선순위 (2026-08-24 전체 점검 기준 · 마감 9/21)

남은 기간 약 4주. 아래 순서대로 처리하면 마감까지 안전하다.

### A. 필수 — 이게 없으면 심사에서 기능이 끊겨 보인다

1. **담은 체험이 체류 계획·예상 비용 탭으로 안 넘어간다.**
   둘러보기는 실제 `contentId`를, 나머지 두 탭은 목업 id(`e1`~`e8`)를 쓴다.
   체험을 담아도 일정표에 안 뜨고 체험비가 0원. 서비스의 핵심 흐름
   (둘러보기 → 계획 → 비용)이 실제로 끊겨 있다.
   → `ScheduleTab`/`CostTab` 실데이터 연동. docs/03-api-check.md §15.
2. **체험 소요시간·가격이 API에 없다 (1번과 함께 결정해야 함).**
   예상 비용의 "체험비" 항목을 어떻게 채울지 제품 판단 필요
   (사용자 입력으로 받기 / 항목 자체를 빼기 / 무료·유료만 표기 등).
3. **새로고침하면 체류 조건이 사라진다.** `SearchContext`가 메모리라
   `/plan/:id`에서 새로고침하거나 URL을 직접 열면 기간·라이프스타일이
   초기화된다. 게다가 배너는 "2주"라고 쓰는데 계산은 7일로 도는
   불일치까지 생긴다(§ 아래 "화면 간 연결" 항목).
   → 조건을 URL 쿼리에 싣거나 `SearchContext`도 localStorage로.
4. **없는 URL이 완전한 빈 화면.** `App.jsx`에 `path="*"` 캐치올이 없다.
   심사위원이 주소를 잘못 입력하면 헤더조차 없는 백지가 나온다.
   → `RegionNotFound`처럼 이미 있는 컴포넌트를 재사용하면 금방 끝난다.
5. ~~**지도가 아직 목업이다**~~ — **완료(2026-08-26).** 지도 4곳 전부
   실제 카카오맵으로 교체했다(추천 결과 미니맵 / 둘러보기 사이드 /
   체류 계획 사이드 / 최종 계획 체류 범위). SDK를 못 불러오면 목업
   셸로 폴백한다. 아래 "카카오맵" 절 참고.
6. **지원 프로그램 실제 공고 수집(팀 작업).** 관광공사 API 범위 밖이라
   사람이 모아야 한다. 구조·입력 양식·상태 자동 계산은 2026-08-26에
   끝냈고(`data/supportPrograms.js` 상단 주석 참고), 지금 12건이
   목업이라 내용만 채우면 된다.

### B. 있으면 좋은 것 — 완성도

7. 토스트(ToastStack) — design 전반에 깔려 있는데 통째로 빠져 있다.
8. 구글 OAuth 실연동 (`VITE_GOOGLE_CLIENT_ID` 비어 있음).
9. 계획 이름 중복 처리(`uniquePlanName`).
10. 숙소 예약 링크를 `contentId` 기반 개별 상세 페이지로.
11. RegionResult/RegionIntro의 추천 점수를 실제 API로.

### C. 안 해도 되는 것 — 판단해서 접어도 됨

12. ~~`overview`(최종 계획) 화면~~ — **구현 완료**(2026-08-26).
    `/plan/:regionId/overview`. design 1446-1696줄을 그대로 옮겼고,
    인쇄·엑셀 내보내기만 UI로 남기고 동작은 아래 15번으로 미뤘다.
13. 마감 임박 알림 설정 — design에서도 죽어 있던 기능.
15. **내보내기(인쇄/PDF·엑셀) 실동작** — 최종 계획 화면의 드롭다운은
    원본대로 있지만 지금은 "내보내기는 아직 준비 중이에요."만 뜬다.
    붙일 것: (a) 인쇄용 CSS — 원본은 `data-print-hide` 속성으로 헤더·
    버튼을 숨기고 `window.print()`를 부른다(design 3384줄). 속성은 이미
    같은 자리에 다 달아뒀으니 `@media print` 규칙만 쓰면 된다.
    (b) 엑셀 — design 2046줄 `exportXlsx(name, days)`가 일정표와
    `cbBars`를 시트 2장으로 만든다. `buildFullSchedule()`과
    `buildCostBars()`가 이미 같은 모양의 데이터를 주므로 직렬화만 하면
    된다. 외부 라이브러리(xlsx) 추가 여부는 판단 필요.
14. 스캐폴딩 스텁 파일 13개 정리(아래 "코드 정리" 항목).

  `animation: slj-bob …`으로 부르면 이름이 `_slj-bob_해시_1`로 바뀌어
  정의를 못 찾는다. 실측으로 확인했다 — SCROLL 표시 이동량 0px.
  죽어 있던 것: 히어로 SCROLL bob, Skeleton shimmer, 다시 만들기 스피너,
  AuthGate·ExploreTab 페이드, ConfirmModal 페이드·라이즈, NameDialog 라이즈.
  - 고친 방법: 전역 유틸리티 클래스(`.slj-anim-*`)를 global.css에 두고 JSX에서
    모듈 클래스와 함께 붙인다. `animation: :global(name)` 문법은 Vite postcss가
    파싱하지 못한다("Double colon" 에러). 값은 옮기기 전 그대로다.
  - [ ] 앞으로 모듈 CSS에 `animation:`을 새로 쓰면 같은 함정에 빠진다.
        전역 클래스를 쓰거나 keyframes를 그 모듈 안에 정의할 것.
- **캐러셀 시작 위치** — design은 페이지 로드와 함께 타이머를 돌려서(2185-2190줄)
  홈 위쪽을 읽다 내려오면 이미 2~3번째 지역이 떠 있었다. IntersectionObserver로
  섹션이 절반 보일 때 1번부터 시작하고 화면 밖에서는 멈추게 했다. 사용자가 직접
  넘긴 뒤에는 자동재생을 되살리지 않는다(design halt 규칙 유지).
- **검증 방법을 바꿨다**: 정지 스크린샷 대신 실제 값 변화로 확인한다.
  bob은 요소 top이 827→833(6px), shimmer는 background-position 변화,
  스피너는 transform 8프레임 모두 다른 값, 캐러셀은 transform 기준
  슬라이드 인덱스 추적.

## 지역 사진 재선별 + 본문 슬라이드 (2026-08-29)

- **왜 다시 골랐나**: 사진은 처음부터 정상 로드(200)됐고 CSS 배경도 맞았다.
  문제는 사진 선택이었다 — 태안 몽산포·서천 춘장대처럼 평평한 백사장과
  잔잔한 바다는 배너의 딥그린 오버레이(72%→60%→76%) 아래에서 단색이 된다.
  하필 데모 기본 지역이 태안이라 "사진이 안 보인다"로 보였다.
- **선별 방법**: 지역명 + 명소명으로 후보를 모으고(76회 호출, 일회성)
  촬영지가 그 지역인 것만 남긴 뒤, **배너와 같은 오버레이를 씌운 컨택트
  시트**를 만들어 형태가 남는 것만 골랐다. 지역당 4장 = 60장.
- **배치**: 첫 장 = 대표(지역 소개 배너 / 추천 결과 카드 / 마이페이지 /
  계획 배너 / 홈 캐러셀), 4장 전체 = 지역 소개 본문 슬라이드.
- **본문 슬라이드**(`RegionIntro/Features.jsx`): design 733-738줄에 자리가
  있었고 우리도 구현돼 있었는데 내용이 목업 그라데이션 4장이었다. 그 자리에
  사진 4장을 넣었다. 장수·간격(3.6초)·크로스페이드(1.1초)는 원본 그대로이고,
  목업 라벨("image · ○○ 풍경") 자리에는 지금 보이는 사진 제목을 쓴다.
- 교체된 대표 사진: 태안(몽산포 → 안면암의 봄), 서천(춘장대 → 장항
  스카이워크), 안동(하회마을 → 월영교의 봄), 삼척(공양왕릉 → 장호항의 여름),
  영주(소수서원 → 무섬마을 외나무다리), 정선·인제·영덕도 형태가 더 뚜렷한
  것으로 바꿨다.
- **런타임 호출은 그대로 0건**이다(정적 상수).
- [ ] 홍성은 갤러리에 쓸 만한 사진이 거의 없다(전체 100건, 대부분 기념비·
      시장 내부). 스카이타워 야경 + 김좌진 생가 + 홍주읍성 + 광천시장으로
      채웠다. 더 나은 사진이 생기면 URL만 바꾸면 된다.
- [ ] 히어로 사진(천장호 전경)이 청양 슬라이드 2번과 같다. 화면이 서로 멀어
      문제되진 않지만 신경 쓰이면 청양 쪽을 다른 장으로 바꾸면 된다.

## UI 다듬기 6건 (2026-08-29)

1. **숙박 카드 버튼 정렬** — 담기 버튼과 예약 링크를 `.actions` 한 줄로 묶었다.
